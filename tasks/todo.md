## 目標
把 `骰俠吹牛王-投注站.html.html` 原型變成可公開分享、多人同時下注即時同步的網頁，
部署到 GitHub Pages，之後用 Claude Code 改完直接 push 上線。

## 已確認的決策
- 權限：**維持全開放**，不做登入或 PIN（朋友間信任制）
- 盤口：只保留「總冠軍」+ 自訂特別投注盤，不預建各階段賽程盤
- 單邊池：沒有對手池時 **1.00x 全額退還、不抽水**
- 身分：裝置記憶暱稱 + 「我的下注」分頁
- 抽水：5–10% 滑桿（沿用），結算時快照該盤實際抽水率

## Review

實作完成，全部項目已勾稽。核心成果與驗證數據：

### 修掉的關鍵 bug：同時下注會吃掉注單
舊版 `saveState()` 是 `db.ref(DB_PATH).set(state)`，每次下注覆寫整棵樹。
對真實 Firebase 實測（測試節點，測完刪除）：

| 寫法 | 12 人同時下注 | 結果 |
|---|---|---|
| 舊版 `set()` 整棵樹 | 送出 12 筆 | **只剩 1 筆，11 筆消失** |
| 新版 `push()` 帳本 | 送出 12 筆 | **12 筆全在，池額正確** |

解法不是加鎖或 transaction，而是換資料模型：
**下注帳本 = 唯一真實來源，只能 append**。彩池、賠率、派彩全部即時推導。
於是下注只是一次 `push()`（key 天生不衝突），池額也不可能跟帳本對不起來。

### 規則收斂：單邊池
測試抓到一個原本沒想清楚的邊界 —— 只有一個選項有人下注、但結果開在
另一個沒人押的選項上。原本會判成「無人押中 → 彩池歸莊」，等於那位
下注者被沒收全部籌碼，可是這盤根本沒有對手池。

收斂為：**全場的錢集中在一個選項上 → 不論開在哪都作廢退款**。
並與「有真正對手池但沒人押中 → 彩池歸莊」明確區分。四種結算狀態：
`paid` / `refund` / `no-winner` / `empty`。

結算預覽文字直接複用 `settleInfo()`，避免預覽與實際派彩用兩套邏輯。

### 第三輪：分階段下注的公平性問題

使用者提出「會分開結算，但賽前可能已有人下總冠軍」。拆成兩件事：

**機制上沒問題**（已驗證 18 項）：盤口彼此完全獨立。結算十六強不會動到
總冠軍盤的池額、賠率或已下注單；抽水率是各盤結算時各自快照的。

**公平性上有真問題**（已用測試量化）：彩池賠率是用結算時的最終池算的，
不是下注當時的池。所以晚下注者能用「已知誰晉級」的資訊進場，卻跟賽前
冒 16 人未知風險的人拿一樣的分潤比例：

```
乙 賽前押選手2 $5000 → 1.02x
丙 十六強後才押選手2 $5000 → 乙掉到 0.98x（押對卻虧錢）
```

決策：**分階段獨立彩池**。

- [x] 「用 16 人名單開新盤」——一鍵開階段盤，不用手打 16 個名字
- [x] 選項標籤改為跟著玩家名單走（不再綁 `group`），改名自動同步
- [x] 「一次結算所有總冠軍系列盤」——列出每盤賠率與派彩供確認，
      一次原子寫入，不會結算到一半斷掉
- [x] 刪除保護改為只鎖 `champion` 這個錨點盤，階段盤可刪

驗證：單元測試 73 → **93 項全過**，新增系列盤辨識 10 項、分階段獨立
彩池 10 項。關鍵斷言：同一情境下乙的賠率維持 1.0230（單一彩池會被稀釋
到 0.9765），丙的錢進不同池、拿不到乙的分潤。

### 第五輪：莊家盤自動調價

使用者指出手動調價來不及：有人押 A $1000、又有人押 B $10000，另一邊的賠率
理論上該上升，但莊家反應不過來。

關鍵認知：純粹依注額重算賠率，數學終點就是彩池公式。差別在莊家盤的賠率是
下注當下鎖定的，所以莊家吸收「調價跟不上」的殘差。這是有價值的混血，不是白做工。

做法——把莊家的初始賠率當先驗，換算成虛擬注額與真實注額相加：

```
O      = Σ(1/初始賠率)
賠率_i = (K + S) / (O × (K×q_i + s_i))    q_i = (1/初始賠率_i)/O
```

- [x] `autoPrice`（預設 true）與 `priorK`（定價黏性，預設 2000）欄位
- [x] 零下注時算出來等於初始價；Σ(1/賠率) 恆等於 O → 莊家利潤率不因錢流動而變
- [x] 安全上下限 1.01 / 50.00
- [x] 盤口顯示初始定價隱含的莊家利潤率，負值時警告
- [x] 可逐盤關閉自動調價改回純手動
- [x] 賠率顯示加上「開 X.XX」讓玩家看得出價格已移動
- [x] **順帶消掉上一輪指出的競態**：自動定價模式下 `oddsAtBet` 改由本地推導，
      與畫面顯示的是同一個數字，不會出現「看到 3.0 卻成交在 1.1」

驗證：單元測試 136 → **157 項全過**，新增自動定價 13 項、邊界 10 項。
實測：初始 甲1.80/乙2.40、黏性 2000，甲被押 $3000 後 → 甲 1.24、乙 6.00，
overround 0.9722 → 0.9731（維持不變）。黏性 20000 → 1.64、黏性 200 → 1.06。

修正一個先前口誤：overround 0.972 是**負利潤率**（−2.8%），不是「利潤率」。
利潤率 = overround − 1，必須為正莊家才有優勢。介面已把這個數字算給莊家看。
