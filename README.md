# 骰俠吹牛王 · 投注站

第一屆骰俠吹牛王賽事的網頁版投注器。採**彩池投注（parimutuel）**計價：同一盤口的所有注額匯入一個池子，
莊家抽水後依比例分給押中的人 —— 所以賠率會隨著大家下注的比例即時浮動，概念跟球版一樣。

## 上線網址

https://wuchiehee03g.github.io/DiceBetPanel/

## 功能

- **即時同步**：所有人開同一個網址，看到同一份資料。任何人下注，其他人畫面上的池額與賠率立刻跟著動。
- **莊家抽水 5–10%**：滑桿調整。結算時會把當下的抽水率鎖在該盤上，之後有人再動滑桿也不影響已結算的盤。
- **總冠軍盤**：16 位玩家，名單可在「賽事管理」裡改。
- **分階段獨立彩池**：每階段開一個獨立的總冠軍盤，賽前下注者的賠率不會被後面
  階段進場的錢稀釋。可一鍵用 16 人名單開新盤、一次結算整個系列。
- **特別投注盤**：自己開題目與選項（例如「決賽是否有人喊哉？」→ 有,沒有）。
- **封盤 / 結算分離**：開骰前先「封盤」停止下注，公布結果後再「結算並派彩」。
- **撤銷結算**：結算按錯了可以撤銷，注單全部保留，撤銷後可改判到正確結果。
- **刪除自訂盤口**：開錯題目可以單獨刪掉，不用整場重置。
- **我的下注**：這台裝置下過的注、狀態、累計損益。
- **匯出 / 匯入備份**：JSON 檔。

## 賠率怎麼算

```
賠率 = 總池 × (1 − 抽水率) ÷ 該選項池額
```

賠率是**含本金**的倍數。例：總池 10000、抽水 7%、你押的選項池額 3000
→ 賠率 = 10000 × 0.93 ÷ 3000 = **3.10x**，押 100 中獎領回 310。

**單邊池特例**：若某盤所有注都押在同一邊（沒有對手池），該盤視為作廢，
**原注 1.00x 全額退還、不抽水**。避免「猜對了卻因為抽水而虧錢」。

若某盤**沒有人押中**（但確實有對手池），彩池全數歸莊。

## 分階段下注：為什麼要開多個總冠軍盤

彩池投注的賠率是用**結算時的最終池**算的，不是你下注當時的池。所以如果總冠軍盤
從賽前一路開到決賽，會出現這個問題：

```
乙 賽前押 選手2 $5000  →  當時賠率 1.02x
十六強打完，大家看到選手2 活下來了
丙 這時才押 選手2 $5000  →  乙的賠率掉到 0.98x
```

**乙押對了卻虧錢。** 丙用「已經知道選手2 晉級」的資訊進場，卻跟賽前冒 16 人
未知風險的乙拿一樣的分潤比例，等於稀釋了乙。

解法是**每階段開一個獨立彩池**。管理面板的「總冠軍系列盤」→ 輸入名稱 →
「用 16 人名單開新盤」，不用手打 16 個名字，選項標籤會跟著玩家名單自動同步。

### 賽事當天的操作順序

| 時機 | 動作 |
|---|---|
| 賽前 | 用「總冠軍 · 賽前」收注 |
| 十六強開打前 | 把「總冠軍 · 賽前」**封盤** |
| 十六強結算後 | 開「總冠軍 · 八強前」新盤收注 |
| 八強開打前 | 把「總冠軍 · 八強前」**封盤** |
| 八強結算後 | 開「總冠軍 · 四強前」新盤收注 |
| …以此類推 | |
| 冠軍出爐 | 管理面板「一次結算所有總冠軍系列盤」→ 選冠軍 → 全部結算 |

**關鍵是開新階段盤時要記得把上一階段的盤封盤**，否則兩個池同時收注就失去分階段的意義了。

批次結算會列出每個盤的賠率與派彩讓你確認後再送出，並用一次原子寫入完成，
不會結算到一半斷掉。結算後每個盤仍可個別「撤銷結算」。

各階段盤的彩池完全獨立 —— 結算其中一個不會動到其他盤的池額、賠率或抽水率。

## 結算按錯了怎麼辦

按已結算盤口上的「**撤銷結算**」。因為派彩是即時從帳本推導、沒有寫死成欄位，
撤銷不需要反向解開任何已發出的派彩 —— 清掉結算狀態，數字就自動回到未開盤的樣子，
**所有注單完整保留**。撤銷後盤口維持封盤，確認正確結果後可以重新結算。

「**刪除盤口**」只對自訂的特別投注盤開放（總冠軍盤不能刪）。
刪除會連同該盤的所有注單一起移除 —— 因為帳本是唯一真實來源，留下對不到盤口的
孤兒注單會讓統計失準。所以會問兩次確認並告知會刪掉幾筆、多少錢。
如果只是想停止收注，用「封盤」而不是刪除。

## 資料存哪裡

Firebase Realtime Database（專案 `dicebetpanel`，區域 asia-southeast1）。
設定寫在 `index.html` 開頭的 `firebaseConfig`。

資料結構 —— **下注帳本是唯一的真實來源**：

```
diceLiarKingState/
  rake                    抽水率 0.05 ~ 0.10
  players/{0..15}         玩家名稱
  markets/{marketId}/     盤口設定：title desc group order locked settled winnerId rakeAtSettle
           options/{optId}  選項：label order
  bets/{pushId}           注單：marketId optionId name bettorId amount ts
```

彩池金額、賠率、派彩**全部即時從 `bets` 推導**，不另外存欄位。
下注只是往 `bets` 做一次 `push()`，所以：

- 多人同時下注不可能互相覆蓋（`push()` 產生的 key 天生不衝突）
- 池額不可能跟帳本對不起來（因為池額就是帳本算出來的）

> 這點很重要：舊版原型是每次下注都 `set()` 整棵樹，兩人同時下注時後寫的會蓋掉前一筆，那筆注就消失了。

## ⚠️ 安全性：目前是完全開放的

資料庫規則目前開放讀寫，頁面上也沒有任何管理員驗證。意思是：

**任何拿到連結的人都可以下注、封盤、結算、改玩家名單、甚至按下「重置整個賽事」。**

這是刻意選擇的信任制（朋友間的賽事）。所以：

1. **連結不要外流**到不認識的人手上。
2. 賽事進行中**定期按「匯出備份」**，這是唯一的震撼後道。

### 日後想收緊的話

較簡單的一層：Firebase 主控台 → Realtime Database → 規則，改成「下注只能新增、不能刪改」，
這樣就算有人開開發者工具也無法抹除已成立的注單：

```json
{
  "rules": {
    "diceLiarKingState": {
      ".read": true,
      "bets": {
        ".write": true,
        "$betId": { ".write": "!data.exists()" }
      },
      "rake":    { ".write": true },
      "players": { ".write": true },
      "markets": { ".write": true }
    }
  }
}
```

要做到真正只有你能結算，就得加 Firebase Auth（Google 登入）並在規則裡鎖定你的 UID。
