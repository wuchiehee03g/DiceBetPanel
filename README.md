# 骰俠吹牛王 · 投注站

第一屆骰俠吹牛王賽事的網頁版投注器。全部盤口都是**莊家盤**：由指定的莊家開價、
承擔賠付風險，賠率會隨大家的下注金額自動調整。

## 玩法：莊家盤

- 對手是該盤的**莊家**，不是其他下注者。所以**不需要有人押相反的結果**，
  單邊下注也能成立。
- 賠率由莊家開，**下注的當下就鎖進你那一筆注單**。莊家之後怎麼改價都不影響
  已成立的注 —— 這是防止「看完大家押哪邊再把賠率改低」的關鍵設計。
- **不抽水**。莊家的利潤來自他開的賠率。
- 莊家**不能在自己當莊的盤上下注**。
- 派彩就是 `下注金額 × 該注鎖定的賠率`，莊家收下所有未中的注。

```
莊家淨收益 = 收到的總注金 − 所有中獎注的派彩總額
```

## 三種盤口分類

| 分類 | 選項來源 | 例子 |
|---|---|---|
| **多選項** | 固定 16 人名單，標籤跟著名單同步 | 誰奪得冠軍、誰最先淘汰 |
| **雙選項** | 從名單挑兩位，或自由輸入兩個標籤 | 單挑誰贏、結束比分大小／單雙 |
| **特殊盤口** | 自由輸入 N 個選項 | 決賽是否有人喊哉 |

## 單挑賽事：一次開三個盤

莊家後台有「開一場單挑賽事」，輸入**賽事編號**與**兩位參賽玩家**後一次建立：

1. `第 N 場 · 誰獲勝` —— 兩位玩家（手動輸入）
2. `第 N 場 · 結束比分 大/小`
3. `第 N 場 · 結束比分 單/雙`

比分指**獲勝者剩餘血格**（每輪五格、歸零淘汰，所以必然是 1~5）：

- **單** = 1、3、5　**雙** = 2、4
- **大／小**分界開盤時可選（預設 3 格以上為大），規則會寫進盤口說明讓大家看得到

同一個賽事編號的三個盤會排在一起，也會標上「第 N 場」的標籤。

## 自動調價

錢大量押向某一邊時，那邊的賠率自動下降、另一邊自動上升，把錢引導過去、壓低莊家
的最大曝險。莊家只要在開盤時設一次初始價。

把莊家的初始賠率當成「先驗」，換算成虛擬注額後與真實注額相加：

```
O      = Σ(1 / 初始賠率)                  莊家開價隱含的總機率
q_i    = (1 / 初始賠率_i) / O
賠率_i = (K + S) / (O × (K×q_i + s_i))     K=定價黏性, S=總注金, s_i=該選項注金
```

兩個性質：

- **零下注時算出來剛好等於初始價**，不會一開盤就跳掉
- **Σ(1/賠率) 恆等於 O**，不管錢怎麼流動，莊家的理論利潤率都不變

安全上下限：賠率不會低於 1.01 或高於 50.00。可逐盤關掉自動調價改回純手動。

### 定價黏性要設多少

**波動大小取決於「單筆上限 ÷ 定價黏性」的比值，不是上限本身。**

| 黏性（上限 5000 時） | 一筆滿額注把 2.00 推到 | 移動 |
|---|---|---|
| 1,000 | 1.09 | 45.5% |
| 20,000（預設） | 1.67 | 16.7% |
| 50,000 | 1.83 | 8.5% |
| 100,000 | 1.91 | 4.5% |

莊家後台的開盤表單會**即時算出這個數字**，調黏性時直接看得到效果，不用心算。

### 莊家利潤率

盤口上會顯示 `Σ(1/初始賠率) − 1`。這個數字必須是**正的**莊家才有長期優勢：

- 開 1.80 / 2.40 → **−2.8%**，價開得太甜，長期對莊家不利
- 開 1.80 / 2.00 → **+5.6%**

## 單筆投注上限

預設 **$5,000**，莊家後台可調。下注時**伺服器端會重新驗證**，不只靠前端擋。

## 資料存哪裡

Firebase Realtime Database（專案 `dicebetpanel`，asia-southeast1）。

```
diceLiarKingState/
  schema: 3
  maxBet                  單筆投注上限
  players/{0..15}         玩家名稱
  markets/{marketId}/     title desc category banker matchNo
                          autoPrice priorK order locked settled winnerId
           options/{optId}  label order odds(初始定價)
  bets/{pushId}           marketId optionId name bettorId amount ts oddsAtBet
```

**下注帳本 `bets` 是唯一的真實來源**，只用 `push()` 新增。注金、賠率、派彩、報表
全部即時推導，不另外存欄位。所以：

- 多人同時下注不可能互相覆蓋（`push()` 的 key 天生不衝突）
- 統計不可能跟帳本對不起來

唯一存在注單上的推導結果是 `oddsAtBet` —— 因為那個值就是當時的協議本身。

## ⚠️ 安全性：目前是完全開放的

資料庫規則開放讀寫，兩個頁面都沒有密碼。**任何拿到莊家網址的人都可以開盤、
改賠率、結算、甚至重置整場賽事。**

這是刻意選擇的信任制（朋友間的賽事）。所以：

1. **莊家網址不要外流**
2. 賽事進行中**定期在後台按「匯出備份」**，這是唯一的震撼後道

日後想收緊：Firebase 主控台 → Realtime Database → 規則，改成「下注只能新增、
不能刪改」：

```json
{
  "rules": {
    "diceLiarKingState": {
      ".read": true,
      "bets": { ".write": true, "$betId": { ".write": "!data.exists()" } },
      "maxBet":  { ".write": true },
      "players": { ".write": true },
      "markets": { ".write": true }
    }
  }
}
```

要做到只有你能結算，得加 Firebase Auth 並在規則裡鎖定你的 UID。
